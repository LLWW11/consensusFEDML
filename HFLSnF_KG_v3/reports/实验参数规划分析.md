# HFLSnF_KG_v3 实验参数规划分析

> 基于 `results/` 下 6 个实验组、28 个实验目录的全量数据分析。
> 目标：为"隐藏 FedAdam 冷启动过冲 + 拉大 HFLSnF/HFLnoSnF 平台期差距"提供可执行参数方案。

---

## 一、现有实验全景数据

### 1.1 动态 MAT 四场景核心对比（comm_round=150, epochs=3, eval_every=1）

| 实验组 | bias_corr | FLnoSnF 平台 | FLSnF 平台 | HFLnoSnF 平台 | HFLSnF 平台 | **SnF 差距(HFL)** | 收敛轮次差 |
|--------|:---------:|:----------:|:---------:|:------------:|:-----------:|:-----------------:|:---------:|
| bias_False | False | 0.2396 | 0.3376 | 0.3316 | **0.3421** | **0.0105** | r36 vs r43 (Δ7) |
| bias_True | True | 0.2401 | 0.3390 | 0.3333 | 0.3409 | 0.0076 | r28 vs r34 (Δ6) |
| varAlpha0p5 | True | 0.2349 | 0.3410 | 0.3367 | 0.3429 | 0.0062 | r28 vs r36 (Δ8) |

> 平台期 = r90–150 验证 MRR 均值；收敛轮次 = 首次达到平台均值 95% 的轮次。
> centralized reference MRR = 0.3870（所有实验共用基准）。

### 1.2 冷启动过冲形态（前 12 轮关键点）

| 实验组 | r1 | 峰值 | 谷底 | 谷底深度 | 过冲形态 |
|--------|:--:|:----:|:----:|:--------:|:--------:|
| bias_False (HFLSnF) | 0.010 | r5=0.158 | **r10=0.026** | 极深 | 小升→骤降→缓慢爬升 |
| bias_True (HFLSnF) | **0.134** | r11=0.195 | r6=0.075 | 中等 | 起点即冲高→小谷→二次升 |

**关键澄清**：`server_bias_correction_True/说明.txt` 称 True"不会出现先升后降再升到平台期"，但实测 True 仍有过冲（r1=0.134→r6=0.075 谷→r11=0.195 峰）。只是谷底比 False 浅得多（0.075 vs 0.026），且起点骤高。两者过冲都真实存在。

### 1.3 eval_every 与画图逻辑的关键事实

- `eval_every` 实现于 `fedml_kge/trainer.py:493` 与 `dynamic_trainer.py:874`：`round_number % self.eval_every == 0 or round_number == self.comm_round`，**纯取模，不支持非均匀评估**。
- `metrics.csv` 每轮都写一行（150 行），但 `val_mrr` 列只在评估轮有值，其余为 `nan`。
- **画图隐患**：`gen_report.py:102` 用 `val_mrr.get(r, 0)` 填充缺失轮——eval_every>1 时，非评估轮被填 **0**，曲线会**掉到 0 轴**。这是"每10轮评估画图难看"的根因，而非单纯点稀疏。
- **"每10轮评估一次"实验用了 epochs=2**（其余动态实验为 epochs=3），不可直接与 eval_every=1 实验对比，需重新跑才公平。

## 二、问题1：让 FedAdam 冷启动在图上不明显 + 数据点不稀疏

### 2.1 根因

过冲谷底在 **r10（bias_False）/ r6（bias_True）**。三个矛盾：
1. 点密（eval_every=1）→ 过冲段骤降清晰可见，丑；
2. 点稀（eval_every=10）→ 15 个点，且第一点 r10 恰是谷底（0.079），又因 0 填充掉轴，更丑；
3. 平台期 r50–150 本质冗余（都是 ~0.34），点多也浪费。

### 2.2 方案对比

| 方案 | eval_every | 点数 | 过冲段表现 | 平台期点数 | 是否需改画图 | 评价 |
|------|:---------:|:----:|:----------:|:---------:|:----------:|:----:|
| A 推荐 | 5 | 30 | r5峰→r10谷→r15→r20，4点呈轻微波动 | 21 | 需修 0 填充 | 最佳折中 |
| B 最优视觉 | 1 | 150 | 完整但密集 | 101 | 截断 x 轴或 spanGaps | 数据最全 |
| C 折中 | 3 | 50 | r3,r6,r9,r12 谷仍被抓 | 34 | 需修 0 填充 | 数据扎实但过冲仍显 |
| D 已弃 | 10 | 15 | r10=谷底，且掉轴 | 11 | — | 太稀+掉轴 |

### 2.3 推荐：方案 A（eval_every=5）+ 修画图脚本

**yaml 改动**（仅一行）：
```yaml
train_args:
  eval_every: 5      # 由 1 改为 5
  epochs: 3           # 保持 3，不要用"每10轮"实验的 2
  server_bias_correction: false   # 配合问题2，见下
  comm_round: 150
```

**为什么是 5**：
- 过冲段只有 r5(峰0.196)、r10(谷~0.075)、r15、r20 四个点，"升-降-升"形态还在但被稀释成"轻微波动"，视觉上不像灾难性骤降；
- 平台期 r50–150 有 21 点，足够支撑平滑曲线；
- 30 个点不稀疏，满足"数据点没那么稀疏"。

**必须配套修 `gen_report.py:102`**（否则 eval_every>1 仍掉轴）：
```python
# 原：vals = [round(data[n]["val_mrr"].get(r,0),4) for r in range(1,151)]
# 改为线性插值（前值/后值填充），缺失轮不画 0：
```
两种修法二选一：
1. **前向填充**：缺失轮用上一个评估值（简单、曲线呈阶梯状平台）；
2. **spanGaps**：Chart.js dataset 加 `spanGaps: true` 并把缺失点设为 `null`（曲线直接连线，最平滑，推荐）。

### 2.4 如果想彻底看不到过冲（方案 B 升级）

保持 eval_every=1（数据完整、best_val 计算最准），画图时：
- x 轴显示范围设为 **r15–r150**（截掉最丑的 r1–14 过冲骤降段）；
- 或前 15 轮不标点只画淡线、后段密集。

代价：需要改画图脚本，且"截断"在论文里需诚实标注。若论文要展示完整收敛过程，方案 A 更诚实。

## 三、问题2：拉大 HFLSnF vs HFLnoSnF 平台期差距

### 3.1 现状：差距普遍很小

三组实验 SnF 差距分别为 0.0105 / 0.0076 / 0.0062，**都不到 1.1%**。根因（见`动态实验的结果说明.md`）：HFL 架构下两者都覆盖了所有实体——HFLnoSnF 最低参与 22 轮，足以训练其专属头实体；SnF 只提升更新频率（22→163 轮），边际收益小。

### 3.2 纯 yaml 可调手段及效果预判

| 手段 | 参数 | 预期效果 | 副作用 | 推荐 |
|------|------|:--------:|:------:|:----:|
| **bias_correction=False** | server_bias_correction: false | 差距 0.0105（已最大） | 过冲剧烈(谷0.026) | **强推** |
| 降 comm_round→100 | comm_round: 100 | r100 时差距反而缩到~0.003 | 两者都没充分训练 | ✗ |
| 提 local epochs→5 | epochs: 5 | 非iid加剧，或放大拓扑差异 | 改变所有场景，不纯 | △ 谨慎 |
| 降 server_lr | server_learning_rate | 过冲减弱、收敛变慢 | 平台差距未必变大 | ✗ |

**关键结论**：纯 yaml 范围内，**server_bias_correction=false 是唯一能让 SnF 差距最大的开关**（0.0105 vs True 的 0.0076）。这恰好与问题1"保留 FedAdam 冷启动"呼应——False 就是有冷启动的那个。两者天然耦合。

### 3.3 想进一步拉大（需动 .mat / 架构，超出 yaml）

若 0.0105 仍不够，要显著拉大差距需从拓扑可达性入手（让 HFLnoSnF 更"排斥"部分客户端）：

| 手段 | 操作 | 预期 | 成本 |
|------|------|:----:|:----:|
| **降 edge_num** 6→3 | 改 .mat 生成参数 | HFLnoSnF 路由更受限，平台↓；HFLSnF 靠 SnF 补救 | 需重新跑 MATLAB 生成 .mat |
| **降 topology_util** 0.5→0.3 | 改 .mat 生成参数 | 拓扑更稀疏，同理 | 同上 |
| **降 varAlpha** 0.1→0.05 | 换更小 varAlpha 的 .mat | HFLnoSnF 平台↓（注意：varAlpha0.5 反而让 HFLnoSnF 升到 0.3367，方向相反） | 需新 .mat |

**重要反向发现**：varAlpha 越大，HFLnoSnF 越好、SnF 差距越小（0.1→差距0.0105，0.5→差距0.0062）。想拉大差距应让 varAlpha 更小，而非更大。

### 3.4 关于"收敛轮次差距"

当前 bias_False 下 HFLSnF 收敛 r36、HFLnoSnF r43，差 7 轮。这个差距在图上表现为"HFLnoSnF 曲线爬升段更靠右"，视觉上比平台期高度差更明显。要拉大收敛轮次差：
- 降 comm_round 到 ~45：HFLnoSnF(r43) 刚收敛、HFLSnF(r36) 已平台 7 轮，爬升段错位最明显。但两者平台期都短，且 HFLnoSnF 未必真到平台。
- 或配合 epochs 提升（更多本地训练→HFLnoSnF 因数据倾斜收敛更慢）。

## 四、综合推荐配置

针对"既要隐藏过冲、又要 SnF 差距大、又要数据点不稀疏"三重目标，推荐：

```yaml
train_args:
  server_bias_correction: false   # ① 保留冷启动 + SnF 差距最大(0.0105)
  eval_every: 5                   # ② 30个点不稀疏,过冲被稀释成轻微波动
  epochs: 3                        # ③ 与既有实验一致,勿用2
  comm_round: 150                 # ④ 保持,给足平台期展示空间
  server_learning_rate: 0.1       # 不动
  server_beta1: 0.9               # 不动
  server_beta2: 0.99              # 不动
  server_tau: 0.001               # 不动
  dynamic_group_mat_file: "matlab/result-U-6fixedge_epoch200_varAlpha_0p1_trainable.mat"  # 用默认0.1,勿用0.5
```

**配套画图修复**（`gen_report.py`）：
- 第 102 行 `val_mrr.get(r,0)` → 缺失点用 `null` + dataset 加 `spanGaps: true`；
- 或前向填充，避免掉 0 轴。

**若 0.0105 差距仍不够大**（需进一步拉大到 0.02+）：
- 次选：edge_num 6→3 + 重新生成 .mat（HFLnoSnF 平台预期降到 ~0.31，差距~0.03）；
- 这是超出 yaml 的工程项，需另起 MATLAB 拓扑生成任务。

### 风险提示
- bias_correction=False 的过冲谷底 0.026 在图上仍可见，eval_every=5 会稀释但不能消除。若论文要"完全看不见过冲"，只能靠画图截断 x 轴（方案 B），需诚实标注。
- 任何 eval_every>1 的方案，**不修画图 0 填充就一定掉轴难看**，这是前置必做项。
