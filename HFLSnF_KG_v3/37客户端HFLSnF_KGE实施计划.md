# 37客户端HFLSnF知识图谱嵌入实施计划

## 一、项目目标

本项目只实现一条主线：

> 在FB15k-237知识图谱补全任务上，将训练数据稳定划分给37个客户端，使用HFLSnF动态参与和两级聚合完成联邦知识图谱嵌入训练，并在完整官方测试集上取得可信、可复现的`0.30至0.35`量级MRR。

这里的`0.30至0.35`是期望量级，不是通过调整测试集、减少候选实体或只评估尾实体强行得到的目标。若真实结果高于`0.35`，应如实报告；若低于`0.30`，应根据诊断结果继续改进训练或聚合，不得更换评估口径来抬高分数。

## 二、正式评估口径

最终成绩必须同时满足以下条件：

- 数据集使用FB15k-237官方训练集、验证集和测试集。
- 测试集包含完整的20,466条测试三元组。
- 候选范围使用全部14,541个实体。
- 同时评估头实体预测和尾实体预测。
- 使用全局已知真实三元组执行filtered过滤。
- MRR为全部头、尾查询倒数排名的微平均。
- 同时报告Mean Rank、Hits@1、Hits@3和Hits@10。
- 只能使用验证集选择最佳模型，禁止根据测试集结果选择轮次或参数。
- 最终报告种子42、43和44的均值、标准差和95%置信区间。

## 五、37客户端数据方案

### 5.1 第一阶段固定使用现有划分

首轮继续使用V2已验证的`balanced_head_entity`划分：

- 客户端总数固定为37。
- 每个头实体的训练三元组只归属于一个客户端。
- 每个客户端约7,354至7,355条训练三元组。
- 272,115条训练三元组无重复、无遗漏。
- 固定种子42时，预期划分哈希保持为：

```text
8bcac64b705ec2db8721de6a36130625a460c11e0da46e2c22bd852ff015fb19
```

首轮不同时修改数据划分和训练目标，避免无法判断性能变化来自哪里。

### 5.2 客户端参与语义

37表示候选客户端总数，不表示每轮37个客户端必须全部参加。

正式HFLSnF继续使用200行MAT调度：

- 每轮参与11至37个客户端。
- 平均每轮参与35.73个客户端。
- 每轮动态形成2至12个边缘组。
- 保持真实SnF动态参与和动态边缘分组。

如果强制每轮37个客户端全部参加，则只能作为无SnF全参与对照，不能称为正式HFLSnF结果。

### 5.3 备用关系感知划分

只有满足以下条件时，才启用关系感知划分实验：

- 集中式强配方MRR达到或超过`0.32`；
- 37客户端HFLSnF仍低于`0.28`；
- 完整方向诊断证明主要问题不是训练未收敛。

备用划分应按关系频次进行负载均衡，使每个关系只分布在少量客户端，同时保证所有训练三元组无重复、无遗漏。该方案必须生成新的划分哈希，并与原划分作为独立实验报告，不能覆盖原结果。

## 六、本地KGE训练修改

### 6.1 双向自对抗负采样

将当前只破坏尾实体的训练方式修改为：

- 一个批次执行头实体负采样；
- 下一个批次执行尾实体负采样；
- 头、尾批次交替出现；
- 或使用关系感知Bernoulli概率决定破坏头还是尾；
- 每个方向都使用自对抗权重强调当前高分困难负例；
- 采样时排除已知真实三元组。

训练必须分别记录：

- 头负采样损失；
- 尾负采样损失；
- 综合本地损失；
- 实际头、尾负样本数量；
- 负样本过滤重采样比例。

### 6.2 频率子采样权重

根据头实体—关系和尾实体—关系的训练频次计算子采样权重，降低超高频模式对本地优化的支配程度。

该权重只作用于训练损失，不改变验证和测试指标。

### 6.3 向量化实现

负采样不得继续使用“每个正样本乘负样本数”的Python逐条循环。

目标实现：

- 批量生成候选实体编号。
- 批量构造头负样本或尾负样本。
- 批量过滤真实三元组。
- 只把最终负样本张量传入GPU。
- 支持固定随机种子复现。

完成向量化之前，不得直接启动256负样本的37客户端正式实验。

### 6.4 首选TransE配置

首轮强配方使用：

```yaml
model: "transe"
embedding_dim: 256
distance_norm: 1
local_objective: "bidirectional_self_adversarial"
fede_gamma: 9.0
adversarial_temperature: 1.0
negative_sample_count: 256
batch_size: 1024
learning_rate: 0.00005
epochs: 2
comm_round: 200
```

选择2个本地epoch的原因：

- V2 C臂在1个本地epoch、200轮下约完成`193.14`次有效全局数据遍历。
- 2个本地epoch约对应`386.28`次有效全局数据遍历。
- 该训练暴露量与强自对抗KGE配方更接近。

如果服务器显存或时间不允许直接使用256负样本，可先用64负样本做链路和趋势验证，但64负样本结果不能直接作为最终正式结论。

## 七、两级逐行计数加权聚合

### 7.1 当前问题

V2的行级聚合只区分“该客户端是否出现过这一参数行”，出现过的客户端等权平均。

这会导致：

- 只出现1次的关系与出现1,000次的关系拥有相同聚合权重。
- 高频实体和高频关系的真实训练贡献被削弱。
- 多个客户端共同更新同一关系时，局部更新容易互相稀释。

### 7.2 V3聚合规则

客户端训练完成后，除参数状态外，还要上传：

- 每个实体行在本地正三元组中的出现次数；
- 每个关系行在本地正三元组中的出现次数；
- 本轮实际训练正三元组数；
- 实体行和关系行有效更新掩码。

边缘节点对每一行执行：

```text
边缘参数行 =
各客户端参数行乘本地行出现次数之和
除以
各客户端本地行出现次数之和
```

云端对各边缘节点继续使用对应行的累计出现次数执行相同计算。

某一行在本轮没有任何客户端更新时，必须保留轮初全局值，不能置零。

### 7.3 聚合审计

每轮至少记录：

- 实体行参与聚合数量。
- 关系行参与聚合数量。
- 未更新行数量。
- 每行贡献客户端数的最小值、均值和最大值。
- 每行累计出现次数的最小值、均值和最大值。
- 边缘聚合与云端聚合后的参数哈希。

必须增加人工小样本测试，手工计算两级逐行计数加权结果并与程序逐元素比较。

## 八、验证与检查点策略

### 8.1 训练期验证

训练期不能再只依赖简单随机的1,000条验证三元组。

建议使用：

- 固定种子生成的4,096条关系分层验证子集；
- 尽可能覆盖全部237个关系；
- 每10轮执行一次；
- 每次保存当前检查点和完整指标；
- 分别记录头MRR、尾MRR和综合MRR。

### 8.2 正式选模

训练结束后：

1. 对所有周期检查点使用完整17,535条验证集复评。
2. 按完整验证集综合MRR选择最佳检查点。
3. 最佳检查点只在完整20,466条测试集上评估一次。
4. 保存最后一轮检查点，避免无法判断是否仍在上升。

### 8.3 禁止事项

- 禁止使用测试MRR选择最佳轮次。
- 禁止只报告尾实体MRR。
- 禁止把2,048条公共测试子集MRR称为完整测试成绩。
- 禁止缩小候选实体范围。
- 禁止在种子42失败后只挑选表现更好的随机种子。

## 九、分阶段执行计划

### 阶段0：V3骨架和回归基线

任务：

- 从V2复制必要源代码到V3。
- 排除结果、缓存和旧实验入口。
- 修正包名、配置路径、结果根目录和IDE入口。
- 保留原37客户端划分哈希和MAT调度哈希检查。
- 使用V3复现V2 C臂配置。

验收：

- V3冒烟测试通过。
- V3 C臂小规模结果与V2在固定种子下模型参数一致。
- V2目录未因V3开发产生新修改。

### 阶段1：无需重训的完整方向诊断

任务：

- 对V2 C臂最佳检查点执行完整官方测试集方向诊断。
- 分别得到头MRR、尾MRR、逐关系MRR和逐查询排名。

验收：

- 完成40,932个头尾查询。
- 诊断结果可解释当前综合MRR主要受哪个方向限制。
- 输出方向诊断摘要和逐关系表。

### 阶段2：集中式强配方校准

任务：

- 实现双向自对抗负采样、频率权重和向量化采样。
- 在完整官方FB15k-237上运行集中式TransE。
- 使用与联邦实验完全相同的模型、损失和评估器。

验收门槛：

- 完整测试MRR目标为`0.32`左右。
- 最低继续门槛为`0.30`。
- 如果低于`0.30`，不得启动高成本37客户端正式实验。

失败处理顺序：

1. 检查头、尾批次是否真正交替。
2. 检查正负得分方向和自对抗权重方向。
3. 检查filtered负采样。
4. 检查频率权重和学习率。
5. 检查是否训练充分。
6. 最后才考虑将骨干切换为RotatE。

### 阶段3：逐行计数加权聚合验证

任务：

- 实现客户端行出现次数统计。
- 实现边缘和云端两级逐行计数加权。
- 增加聚合人工黄金测试。
- 运行合成知识图谱联邦冒烟。

验收：

- 手工结果与程序逐元素一致。
- 未更新参数行严格保留全局值。
- 两级聚合与将所有贡献按相同计数一次性合并数学等价。
- 聚合统计文件完整。

### 阶段4：种子42正式HFLSnF实验

任务：

- 使用37客户端、原200行动态MAT和强TransE配方训练。
- 运行200轮、2个本地epoch。
- 周期保存检查点。
- 训练后完整验证选模和完整测试。

判定：

| 种子42结果 | 下一步 |
|---|---|
| `MRR >= 0.30` | 进入种子43和44复现 |
| `0.28 <= MRR < 0.30` | 分析头尾差距，优先调整聚合计数或训练预算 |
| `MRR < 0.28`且集中式`>= 0.32` | 诊断联邦聚合和数据划分，不继续机械增加轮数 |
| 集中式和联邦均低于`0.30` | 修复本地KGE配方或切换RotatE |

### 阶段5：多种子正式验收

任务：

- 固定全部配置和代码版本。
- 运行种子42、43和44。
- 汇总均值、标准差、置信区间和头尾方向指标。

最终验收：

- 三个种子全部完成。
- 平均MRR达到`0.30至0.35`期望量级。
- 头MRR和尾MRR不存在异常失衡。
- Hits@1、Hits@3和Hits@10与MRR变化方向基本一致。
- 结果包含完整配置、数据哈希、拓扑哈希、初始模型哈希和代码版本。

## 十、备用RotatE路线

只有在集中式TransE强配方无法达到`0.30`时，才启动RotatE。

备用路线要求：

- 保留相同37客户端划分。
- 保留相同200行MAT调度。
- 保留相同两级逐行计数加权。
- 保留相同完整评估口径。
- 先完成集中式RotatE校准，再运行联邦。
- 不得同时修改模型、数据划分和拓扑。

这样才能判断性能变化来自KGE骨干，而不是其他实验条件。
