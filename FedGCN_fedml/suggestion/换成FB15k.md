**换成 FB15k-237 这类知识图谱数据集，会比 Cora/Citeseer 更适合你的 IoA 叙事。**但与此同时，改造难度会明显高于“普通 GCN 替换 CNN”，因为任务、模型、客户端划分和聚合对象都发生了变化。

最关键的一点是：

> 不应把 FB15k 中的实体直接解释成智能体，而应把每个客户端解释成一个智能体或智能体群组，把客户端持有的局部知识图谱解释成它掌握的知识。

这样场景会比较自然：

```text
智能体 A：掌握人物和组织关系
智能体 B：掌握地点和事件关系
智能体 C：掌握作品和作者关系
                  ↓
各智能体训练局部知识表示模型
                  ↓
边缘智能体聚合区域知识
                  ↓
云端形成全局共享知识表示
                  ↓
补全各智能体本地缺失的事实
```

这比“不同客户端分别拥有一部分论文引用网络”更接近 IoA 中的**分布式知识持有、知识融合和协同推理**。

------

# 一、FB15k-237 比 Cora 更接近 IoA 的地方

Cora 的基本数据形式是：$G=(V,E,X,Y)$

其中：

- $V$：论文；
- $E$：引用关系；
- $X$：论文词袋特征；
- $Y$：论文类别。

任务是：$\text{给定论文特征和引用邻居，预测论文类别}$

它仍然主要是一个节点分类任务。

而 FB15k-237 的基本形式是三元组：$(h,r,t)$

例如：$(\text{Barack Obama},\text{place of birth},\text{Honolulu})$

其中：

- $h$：头实体；
- $r$：关系；
- $t$：尾实体。

目标通常是根据已有知识推断缺失实体或关系：$(h,r,?)\rightarrow t$

或者：$(?,r,t)\rightarrow h$

这对应的不是普通分类，而是：

- 事实补全；
- 关系预测；
- 语义关联发现；
- 隐式知识推断。

知识图谱补全本身就是利用已知三元组预测缺失事实；R-GCN 等模型也专门针对知识图谱的多关系结构，用于链路预测和实体分类。([微软](https://www.microsoft.com/en-us/research/publication/modeling-relational-data-with-graph-convolutional-networks/?utm_source=chatgpt.com))

所以它更容易形成 IoA 叙事：

> 各智能体拥有不完整、异构或局部的知识，通过分层联邦学习形成共享知识表示，从而提升各智能体对未知事实的推断能力。

这比“协同识别手写数字”或者“协同判断论文类别”都更合理。

------

# 二、优先使用 FB15k-237，而不是原始 FB15k

建议使用：

```text
FB15k-237
```

而不是：

```text
FB15k
```

原始 FB15k 中存在较多互为逆关系或高度冗余的关系，例如训练集中出现：$(h,r_1,t)$

测试集中可能出现几乎等价的：$(t,r_2,h)$

模型可能通过这种关系泄漏获得很高的测试结果，而不是真正完成关系推理。

FB15k-237 是从 FB15k 中进一步整理得到的知识库补全数据集，主要用于减少这类可逆关系泄漏；其三元组来源于 Freebase。([ACL Anthology](https://aclanthology.org/W15-4007/?utm_source=chatgpt.com))

因此论文中最好直接使用：

- FB15k-237；
- WN18RR；
- 或后续更贴近动态任务的知识图谱。

------

# 三、不能继续使用原来的普通 GCN

这是最大的模型变化。

Cora 中的边基本只有一种语义：

```text
论文 A 引用论文 B
```

普通 GCN 使用单一邻接矩阵：

$ H^{(l+1)} = \sigma\left(\tilde A H^{(l)}W^{(l)}\right)$

但 FB15k-237 中有大量不同关系：

```text
出生地
国籍
职业
所属组织
作品作者
电影导演
人物配偶
```

如果将所有关系压缩成一个邻接矩阵，就会把：$(\text{人物},\text{出生地},\text{城市})$和：$(\text{人物},\text{配偶},\text{人物})$

混为同一种边，丢失知识图谱最重要的关系语义。

因此有两条可选路线。

------

## 路线 A：知识图谱嵌入模型

这是最适合你短期迁移的方案。

可以选择：

- TransE；
- DistMult；
- ComplEx；
- RotatE。

例如 TransE 假设：$\boldsymbol h+\boldsymbol r\approx\boldsymbol t$

正三元组的评分函数为：

$f(h,r,t) =\lVert\boldsymbol h+\boldsymbol r-\boldsymbol t\rVert$

正确三元组的距离应尽可能小，错误三元组的距离应较大。TransE 的设计目标就是将多关系数据中的实体和关系映射到低维向量空间。([NeurIPS 会议论文集](https://proceedings.neurips.cc/paper/2013/hash/1cecc7a77928ca8133fa24680a88d2f9-Abstract.html?utm_source=chatgpt.com))

它的优点是：

- 代码简单；
- 参数结构清楚；
- 训练速度快；
- 容易嵌入你的 HFL 框架；
- 与 iRML 仓库原有的 TransE 语义表示一致；
- 比 R-GCN 更容易先跑通。

缺点是它不是传统意义上的 GCN，而是 KGE，即知识图谱嵌入。

但对你的论文而言，这未必是缺点，因为你真正需要的可能是：

> 分层联邦知识图谱嵌入或分层联邦知识表示学习。

而不一定非要强调 GCN。

------

## 路线 B：关系图神经网络

例如：

- R-GCN；
- CompGCN；
- SACN；
- 其他关系感知 GNN。

R-GCN 对每种关系使用关系相关的变换：

$ h_i^{(l+1)} = \sigma\left(\sum_{r\in\mathcal R}\sum_{j\in\mathcal N_i^r}\frac{1}{c_{i,r}}W_r^{(l)}h_j^{(l)}+W_0^{(l)}h_i^{(l)}\right)$

其中：

- $\mathcal R$ 是关系类型集合；
- $\mathcal N_i^r$是通过关系 $r$ 与节点 $i$相连的邻居；
- $W_r$ 是关系专用参数。

R-GCN 就是为现实知识库中的高度多关系图设计，并用于缺失三元组预测。([微软](https://www.microsoft.com/en-us/research/publication/modeling-relational-data-with-graph-convolutional-networks/?utm_source=chatgpt.com))

完整知识图谱补全模型一般是：

```text
知识图谱
   ↓
R-GCN 编码器
   ↓
实体表示
   ↓
DistMult/ConvE 等解码器
   ↓
三元组评分
```

例如：

$z_h,z_t =operatorname{RGCN}(G)$

然后通过 DistMult 评分：$ f(h,r,t)z =_h^\top\operatorname{diag}(r)z_t$

这条路线更符合“联邦 GCN”，但迁移工作量明显更大。

------

# 四、最困难的问题是实体嵌入怎么聚合

CNN 的所有客户端模型结构完全相同：

```text
卷积层参数形状一致
全连接层参数形状一致
```

所以可以直接 FedAvg。

但知识图谱模型包含实体嵌入表：$E\in\mathbb R^{|\mathcal V|\times d}$

和关系嵌入表：$R\in\mathbb R^{|\mathcal R|\times d}$

问题在于，不同客户端可能拥有不同实体。

例如：

```text
客户端 1：
Obama、USA、Honolulu

客户端 2：
Einstein、Germany、Physics
```

客户端 1 的第 10 行实体嵌入和客户端 2 的第 10 行实体嵌入很可能对应完全不同的实体。

因此不能直接做：

$ E_{\mathrm{global}} = \frac{E_1+E_2}{2}$

否则是在把不同实体的向量错误地相加。

这是从 CNN/HFL 转向联邦知识图谱时最需要处理的问题。

------

# 五、根据客户端知识图谱关系，有三种划分方案

## 方案一：所有客户端共享统一实体和关系编号

先建立全局映射：

```text
entity2id
relation2id
```

所有客户端模型都包含完整的实体嵌入表和关系嵌入表，只是各客户端拥有不同的训练三元组。

例如：

```text
Client 1:
训练 triple 子集 T1

Client 2:
训练 triple 子集 T2

Client 3:
训练 triple 子集 T3
```

但是所有客户端都维护：$E_k\in\mathbb R^{|\mathcal V|\times d}$,$R_k\in\mathbb R^{|\mathcal R|\times d}$

这样可以直接使用 FedAvg。

### 优点

- 最容易实现；
- 与现有 HFL 框架最兼容；
- 所有 `state_dict` 形状一致；
- 适合快速验证。

### 缺点

- 客户端虽然没有原始三元组，却知道完整实体词表；
- 每个客户端维护完整嵌入表，内存和通信开销较高；
- 联邦隐私和知识隔离的真实性较弱；
- 大量未在本地出现的实体嵌入不会被有效更新。

这个方案适合作为第一版，但论文中要明确它是：

> 统一知识模式下的分布式三元组持有场景。

------

## 方案二：每个客户端只维护本地实体

每个客户端持有：$G_k=(V_k,R_k,T_k)$

其中实体集合不同：$V_i\neq V_j$

只对重叠实体进行聚合：$V_i\cap V_j$

例如：

```text
Client 1:
Obama, USA, Honolulu

Client 2:
Obama, President, White House
```

`Obama` 是共享锚点实体，而其他实体保持本地化。

此时服务器需要进行掩码聚合：

$e_v^{t+1}=\frac{\sum_{k:v\in V_k}n_{k,v}e_{k,v}^{t+1}}{\sum_{k:v\in V_k}n_{k,v}}$

只有持有实体 (v) 的客户端参与该实体的聚合。

这类思路更接近已有联邦知识图谱嵌入研究。FedE 就是针对多个相关但分离的知识图谱，在不直接交换原始三元组的情况下进行知识图谱嵌入学习。([arXiv](https://arxiv.org/abs/2010.12882?utm_source=chatgpt.com))

### 优点

- 更符合真实多智能体局部知识；
- 通信量更低；
- 个性化知识可以保留；
- 可以研究知识重叠率。

### 缺点

- 不能使用普通完整 `state_dict` FedAvg；
- 必须维护实体 ID 对齐；
- 需要设计共享实体掩码；
- 客户端掉线后的实体聚合更加复杂。

这适合作为后续正式方案，但不适合第一步就实现。

------

## 方案三：客户端按照关系领域划分

例如：

```text
Agent 1：
人物—出生地
人物—国籍
人物—职业

Agent 2：
电影—导演
电影—演员
电影—制片公司

Agent 3：
组织—所在地
组织—成员
组织—所属行业
```

每个客户端掌握同一世界的不同知识方面。

这种设置最容易解释为：

> 异构智能体拥有不同领域能力和专业知识。

它非常接近 IoA 中的专业智能体：

- 医疗智能体；
- 交通智能体；
- 金融智能体；
- 通信智能体；
- 调度智能体。

但它也是最困难的方案，因为各客户端的关系集合不同：$R_i\neq R_j$

不能简单聚合关系嵌入。

可能需要：

- 只聚合共享实体；
- 只聚合公共关系；
- 关系嵌入对齐；
- 知识蒸馏；
- 共享编码器、私有解码器；
- 个性化联邦学习。

从 IoA 解释上最好，从短期代码迁移上最难。

# 六、我建议你的第一版怎样做

基于你现在已有 HFL 框架，建议先选择一个折中方案：

## 数据集

使用：

```text
FB15k-237
```

## 模型

第一步使用：

```text
TransE
```

或者：

```text
DistMult
```

不要一开始就使用 R-GCN。

## 客户端划分

不要纯随机打散全部三元组，建议采用：

```text
实体聚类/图社区划分
        ↓
每个客户端得到一个局部知识子图
        ↓
保留一定比例的边界共享实体
```

可以设：$G_k=(V_k,E_k)$

并控制客户端之间的实体重叠率：

$\rho=\frac{\left|V_i\cap V_j\right|}{\left|V_i\cup V_j\right|}$

实验设置例如：

```text
低重叠：ρ = 0.1
中重叠：ρ = 0.3
高重叠：ρ = 0.5
```

第一版仍然使用统一全局实体编号，以保证参数形状一致；但本地损失只使用客户端拥有的三元组。

# 七、如何嵌入你现有的分层 HFL

可以把原来的流程：

```text
FEMNIST 图片
    ↓
客户端 CNN
    ↓
边缘 FedAvg
    ↓
云端 FedAvg
```

替换为：

```text
局部知识三元组
    ↓
客户端 TransE/KGE
    ↓
边缘聚合区域知识嵌入
    ↓
云端聚合全局知识嵌入
```

客户端 (k) 的本地目标可写成：$\mathcal L_k=\sum_{(h,r,t)\in T_k} \left[ \gamma + f(h,r,t)f(h',r,t')\right]_+$

其中：

- $(h,r,t)$ 是真实三元组；
- $(h',r,t')$是通过替换头实体或尾实体产生的负样本；
- $\gamma$是间隔；
- $f$是 TransE 距离。

本地训练后上传：

```text
实体嵌入
关系嵌入
可能还有编码器参数
```

边缘服务器聚合：$ \Theta_e=\sum_{k\in\mathcal C_e}\frac{|T_k|}{\sum_j|T_j|}\Theta_k$

云端进一步聚合：

$ \Theta_g=\sum_e\frac{|T_e|}{\sum_s|T_s|}\Theta_e$

其中权重从原来的图片样本数改为本地三元组数：$n_k=|T_k|$

------

# 八、实验指标必须改变

MNIST/FEMNIST 常用：

```text
Accuracy
Loss
```

知识图谱补全通常使用：

- MRR；
- Mean Rank；
- Hits@1；
- Hits@3；
- Hits@10。

例如给定测试三元组：$(h,r,t)$

将尾实体替换为所有候选实体：$(h,r,e_1),(h,r,e_2),\ldots$

模型给所有候选打分，观察正确尾实体 (t) 的排名。

倒数排名为：$RR=\frac{1}{\operatorname{rank}(t)}$

所有测试样本平均得到：

$MRR=\frac{1}{N}\sum_{i=1}^{N}\frac{1}{\operatorname{rank}_i}$

Hits@10 表示真实实体进入前 10 名的比例。

这些指标比简单三元组分类准确率更能反映推理能力。

------

# 九、掉线实验在知识图谱场景下会更有意义

原来 MNIST 中客户端掉线表示：

> 少上传了一部分图片训练结果。

知识图谱中客户端掉线可以解释为：

> 某一知识来源或某一领域智能体暂时无法参与全局知识融合。

可以设计四类掉线。

## 1. 随机知识源掉线

随机客户端无法上传。

## 2. 关键实体持有者掉线

优先让拥有高频实体或高中心性实体的客户端掉线。

例如客户端持有大量与某些核心实体相关的三元组。

## 3. 关键关系持有者掉线

例如某个客户端主要持有：

```text
location
profession
nationality
```

等关系，它掉线后检查对应关系上的 Hits@K 是否下降。

## 4. 边缘区域整体失效

某个边缘服务器及其下属全部知识源断开。

这时可以测量：$\Delta\mathrm{MRR}=\mathrm{MRR}_{\mathrm{normal}}-\mathrm{MRR}_{\mathrm{failure}}$

还可以按关系分别测量：$\mathrm{MRR}_r$

这样能够说明：

> 不同网络故障会导致不同语义领域的知识缺失，而不是仅仅造成总体准确率下降。

这与你的可靠性、边缘中继和掉线研究会结合得更自然。

# 十、它仍然不是完整的 LLM 多智能体推理

使用 FB15k-237 后，你的任务会从：

```text
图像分类
```

升级为：

```text
分布式知识表示与知识补全
```

它确实更接近 IoA，但仍然不是：

- 自然语言对话；
- LLM 推理轨迹；
- 动态规划；
- 工具调用；
- 智能体行动协作；
- 针对某个问题的答案共识。

FB15k-237 是静态、封闭世界的知识图谱补全基准。它假设实体集合和关系集合基本固定；开放世界知识图谱研究才进一步允许测试阶段出现未见实体。([AAAI](https://aaai.org/papers/11535-open-world-knowledge-graph-completion/?utm_source=chatgpt.com))

因此论文中应当将它称为：

> **面向 IoA 分布式语义知识协作的代理任务。**

不要直接声称：

> 完整模拟了 LLM 智能体协同推理。

# 十一、从你的研究目标出发，我更推荐哪一种

我建议使用以下路线：

```text
第一步：
FB15k-237 + TransE + 二级 FedAvg

第二步：
FB15k-237 + TransE + 现有 HFL

第三步：
加入客户端掉线和边缘节点失效

第四步：
从全参数聚合改为共享实体掩码聚合

第五步：
条件允许时把 TransE 换成 R-GCN + DistMult
```

这样做的原因是：

| 方案                  | IoA贴合度 | 实现难度 | 与现有HFL兼容性 |
| --------------------- | --------- | -------- | --------------- |
| Cora + 普通 GCN       | 中        | 低       | 高              |
| FB15k-237 + TransE    | 较高      | 中       | 较高            |
| FB15k-237 + R-GCN     | 高        | 较高     | 中              |
| 异构多KG + 个性化联邦 | 很高      | 高       | 较低            |
| LLM多智能体真实任务   | 最高      | 很高     | 很低            |

对你目前“短期内基于已有 HFL 实验形成一篇论文”的目标，**FB15k-237 + TransE/DistMult + 分层联邦聚合**可能比直接迁移 iRML 的联邦 GCN 更合适。

最终论文主线可以改为：$\boxed{\text{面向智能体互联网的可靠分层联邦知识图谱嵌入}}$

或者：$\boxed{\text{面向分布式智能体知识协作的云边端联邦知识图谱补全}}$

它既保留你已有的 HFL、掉线、边缘聚合和可靠性工作，又比 MNIST、FEMNIST 和 Cora 更有明确的语义推理含义。
