# HFLSnF_KG_v5 为何优于 v3/v4 — 深度分析报告

> 分析对象：FB15k-237 上的分层联邦知识图谱嵌入（HFL KGE），TransE + RowCountWeightedFedAvg + FedAdam，37 客户端 → 6 边缘服务器 → 云端。
> 结论先行：**v5 的性能提升完全来自分区策略创新，训练侧三版字节级一致。**

---

## 一、核心结论

v3 → v4 → v5 三个版本中，**12 个训练/聚合核心文件（aggregation.py、server_optimization.py、trainer.py、dynamic_trainer.py、model_trainer.py、negative_sampling.py、model.py、objectives.py、fedadam_stage1/2.py、final_dynamic_fedadam.py、final_stochastic_fedadam.py）的 MD5 哈希完全相同**——不是"逻辑相同"，而是同一份文件被原样继承。

因此 v5 相对 v3/v4 的全部性能差异，**唯一变量是客户端数据分区策略**：

| 版本 | 分区策略 | 说明 |
|------|----------|------|
| v3 / v4 baseline | `balanced_head_entity`（头实体均衡互斥） | 每个头实体唯一归属一个客户端，三元组数严格均分（std<1） |
| **v5 新增** | `semantic_domain_graph_local_balanced`（语义域图局部均衡） | 按 Freebase 顶级语义域 + 头实体打包，多重启贪心分配，语义纯度 92%、负载容差 5% |

其余超参（模型 dim=256、margin=1.0、FedAdam lr=0.05/β1=0.9/β2=0.99/τ=0.001/bc=False、comm_round=150、local_epoch=3、batch=1024、client_lr=5e-5、neg_sample=256、拓扑 util=0.6/fixed/6edge）**三版完全一致**，且 v5 的 `graph_semantic_formal150_contract.json` 有 60+ 项配置校验全部 passed，包括"语义纯度提升门禁""关系 JS 散度提升门禁""局部实体复用提升门禁"三项分区质量门禁。

## 四、因果链：为什么语义图分区能提升联邦 KGE

v5 的 `partition_train_triples_by_semantic_domain_graph_local` 做了四件事，每件都直接改善联邦学习的信息流：

**1. 语义域提取 + 不可拆分包（`_SemanticPacket`）**
从 Freebase 关系路径（如 `/film/film/starring/...`）提取顶级域（`film`），按 `(domain, head_id)` 把三元组打包成不可拆分单元。保证"同一头实体在同一语义域的三元组"永不分离——这是头实体嵌入一致训练的前提。

**2. 主域配额（最大余数法）**
按各语义域的三元组占比，用最大余数法把 37 个客户端的名额分配给各域（如 film 占比高则分到多个客户端）。每个客户端被指定一个"主域"。

**3. 多重启贪心分配（8 次取最优）**
对每个包，按"主域匹配优先 → 图增量小优先（包内实体与客户端已有实体重叠多）→ 负载低优先"的三级键贪心分配，带硬上界负载约束。8 次不同随机种子重启，选"违规最少 + 偏差最小 + 主域占比最高 + 实体复制因子最低"的候选。

**4. 低负载修复**
对低于下界的客户端，从高负载客户端批量迁移"语义损失最小 + 图增量最小"的包，仍守住负载上下界。

这套机制产生了三个直接改善联邦效果的性质：

- **(A) 本地梯度一致性**：每客户端 92% 三元组同属一域、仅 4.68 种关系 → 本地 SGD 的嵌入更新方向高度一致。baseline 客户端混杂所有 237 种关系、所有语义域 → 梯度方向互相打架，聚合后部分抵消。
- **(B) 实体图局部协同**：v5 客户端实体图最大连通分量占 98.5% → 相关实体在同一客户端被协同优化，形成自洽的局部嵌入子空间。baseline 实体散落在 9.75 个客户端，本地无法形成协同。
- **(C) 头实体嵌入质量**：`_SemanticPacket` 保证同头同域三元组不拆 → 头实体嵌入在语义一致的上下文里被训练；RowCountWeightedFedAvg 按行加权 + FedAdam 在服务端合理整合该头实体跨多个语义切片的更新。baseline 头实体虽互斥集中，但所在客户端关系混杂、负采样候选跨域，嵌入被噪声干扰。

**为什么 head MRR 提升最大（+20.9%）**：TransE 的链接预测 rank head 直接依赖头实体嵌入质量。v5 让头实体嵌入在"语义聚焦子空间"被一致优化且跨切片合理聚合，所以头实体预测受益最显著；tail 提升较小（+9.3%）因为尾实体天然分散在多个客户端的多个包中。

## 五、证据闭环

1. **唯一变量**：训练侧 12 文件 MD5 一致 + contract 60+ 项配置校验 passed → 排除训练/聚合/超参影响。
2. **分区质量可证**：三项门禁（语义纯度 / 关系 JS 散度 / 局部实体复用）passed → v5 分区在三个维度均优于 baseline。
3. **结果可复现**：3 个独立种子，v5 均显著优于 baseline，差距远超种子方差。
4. **负载未牺牲**：v5 max_relative_load_deviation=0.04997 < 0.05 容差，CV=4.3% → 没有为了语义纯度引入 straggler。

---

## 六、一句话总结

> **v5 = v3/v4 的训练框架（一字未改） + 全新的"语义域 + 图局部性"分区策略。** 后者让每个客户端成为语义聚焦的"关系专家"，使本地梯度一致、实体协同优化、聚合冲突减少，从而在 MRR/Hits 全面提升 10–21%，其中头实体预测提升最猛（+20.9%）。这是数据划分层面的创新，而非算法层面的改动。
