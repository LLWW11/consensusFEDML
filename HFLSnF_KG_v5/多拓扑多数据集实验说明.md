# 多拓扑、多数据集联邦实验说明

本轮增加 OPEN＋WN18RR 的种子42三方法对照，顺序为 HFLSnF、HFLnoSnF、FLnoSnF。训练参数沿用第五版学习率为 `5e-4` 的联邦平均配方。当前已完成真实数据和调度预检、临时小图的处理器训练闭环；尚未产生正式显卡训练结果。

## 参与调度的来源与含义

本轮使用 `Topo_other/OPEN/Result_JICN3/variance_control/jieguo_OPEN_epoch1000_varAlpha_0p1_analysis.mat` 中的受控参与人数。原始文件仅完成统计收缩，参与映射没有同步重建，且未保存 FLnoSnF 的客户端身份，不能直接用来训练。

准备入口据此生成独立文件 `artifacts/topologies/open_varalpha0p1_reconstructed.mat`：尽量保留原有分层联邦客户端及边缘分组；人数不足时按累计参与次数较少者补位，人数超出时优先保留累计参与较少者。平局采用固定种子42产生的客户端优先级。FLnoSnF 同样按累计参与次数补齐身份。

该文件属于**合成参与调度**，元数据明确保存 `schedule_provenance=synthetic_reconstruction_from_varctrl_counts`、`physical_feasibility_validated=0`、来源文件摘要和重建种子。它不表示重新执行过网络优化，也不证明调整后的参与集合满足原链路约束。训练比较用于观察这一受控调度下的学习行为。原优化结果和统计文件保持原样。

人数与受控字段逐轮精确一致。由于人数必须为整数，完整1,000轮在利用率0.6时的实际方差比例分别为0.099844、0.099987、0.099939，接近目标0.1；三种方法均保持各自原1,000轮均值。

## 数据与划分

两个数据集均读取 `train.txt`、`valid.txt`、`test.txt` 三列文本，实体作为字符串保留前导零；按训练、验证、测试的首次出现顺序统一编号，不依赖随附字典。文件缺失、内部重复、跨划分重复会报错，显式错误目录不会回退到其他数据源。

| 配置名称 | 默认目录（相对于本项目） | 自动语义域 |
|---|---|---|
| `fb15k-237`，兼容 `fb15k237` | `data/FB15k-237` | Freebase 顶级关系路径 |
| `wn18rr` | `data/wn18rr` | 11种关系名 |

名称忽略大小写。WN18RR 的关系语义域表示词汇关系类型，并非主题领域标签。两个数据集沿用相同的“语义域×头实体”不可拆分包、实体图局部性、最大余数主域配额、±5%负载约束及8次确定性重启。不同关系语义域可以包含同一个头实体，不要求实体在客户端之间互斥。

真实 WN18RR 为86,835条训练、3,034条验证、3,134条测试，共40,943个实体、11种关系。384个实体只在验证或测试出现，保留原始划分及全部候选实体。

本轮18客户端分区得到每客户端4,583～4,950条训练事实，最大相对负载偏差4.9991%，按三元组加权的主域纯度约93.58%。分区摘要为：

```text
8c519d5a074e0c64a5c738968d9e576ce8b6b1f6343b2a2cb406fc1ade08569c
```

原 FB15k-237 新旧入口编号和张量一致；37客户端、种子42的原分区摘要仍为 `fe461e19b484201766e19cb00b12eae026ac58de09a793f6044b47aa3ac54db2`。

## 配置与拓扑切换

新增配置位于 `configs/multi_topology_dataset/`，三个文件分别对应三种方法，默认均使用 WN18RR 和 OPEN。

```yaml
data_args:
  dataset: wn18rr
  # Optional explicit directory, relative to HFLSnF_KG_v5 or absolute.
  # data_dir: data/wn18rr
  partition_domain_extractor: auto
train_args:
  network_topology: open
  # Optional explicit MAT path; its TopoOption must match network_topology.
  # dynamic_group_mat_file: artifacts/topologies/open_varalpha0p1_reconstructed.mat
```

上面是需要修改的字段示例，运行时使用完整配置文件。同场景三份配置需同步修改共同字段。

| 拓扑选择 | 默认调度路径（相对于本项目） | 客户端规模 |
|---|---|---|
| `open` | `artifacts/topologies/open_varalpha0p1_reconstructed.mat` | 18，4个固定边缘槽位 |
| `metro` | `../Topo_opt/postprocess/result-U-6fixedge_epoch200_hard_varAlpha_0p1_trainable.mat` | 37，6个固定边缘槽位 |
| 其他名称 | 必须显式提供标准调度 MAT | 根据文件元数据推导 |

未知拓扑仍须提供现有解析器支持的逐轮人数及参与映射字段；这不是任意网络文件的自动优化入口。客户端总数由非云节点数推导；显式填写的客户端数量不一致会拒绝运行。FLnoSnF 使用单层聚合，其 `edge_num` 为1；分层方法从固定边缘槽位数推导。

默认配置使用 `{network_topology}`、`{dataset}`、`{random_seed}` 展开结果目录和运行名，避免切换后名称混淆。没有 `network_topology` 字段的历史配置保留原入口行为。

## 本轮共同配方

| 项目 | 设置 |
|---|---|
| 随机种子与数据分区种子 | 42 |
| 模型 | TransE，256维，L1距离 |
| 本地优化器 | Adam，每次本地训练重置优化器状态 |
| 学习率 | `learning_rate = lr = 5e-4` |
| 联邦聚合 | FedAvg，`row_count_weighted` |
| 训练预算 | 150轮，每轮每个参与客户端本地3个周期 |
| 批量与负样本 | 1,024；每正样本256个负样本 |
| 目标 | 头尾交替双向自对抗，gamma＝9，温度＝1 |
| 网络参数 | 利用率0.6，严格回放前150轮，不循环 |
| 验证选模 | 每轮验证，按验证MRR恢复最佳模型 |
| 验证数据 | 上限4,096，WN18RR实际使用全部3,034条 |
| 测试 | 训练不执行测试，完成后用独立入口完整评估 |
| 正式设备 | CUDA，不允许回退到处理器训练 |

前150轮实际统计如下，不能把完整1,000轮的均值、方差约束直接套用到这个窗口。方差采用样本方差；有效全数据遍数为实际参与客户端的正样本数量之和乘本地周期数，再除训练集大小。

| 方法 | 平均参与人数 | 人数方差 | 最少～最多 | 有效全数据遍数 |
|---|---:|---:|---:|---:|
| HFLSnF | 17.747 | 0.7005 | 13～18 | 443.652 |
| HFLnoSnF | 10.567 | 2.4754 | 7～13 | 264.133 |
| FLnoSnF | 4.913 | 0.9522 | 4～9 | 122.830 |

三方法使用同一数据分区与初始化，前150轮均覆盖全部18个客户端。其实际训练数据量不同，结果差异同时包含参与预算与调度影响，不能单独归因于聚合操作。

## 运行步骤

在 `D:\1\1myworkcode` 执行。显卡机器须安装可用的 CUDA 版 PyTorch 和既有 FedML 依赖。

已经存在重建调度时可以直接预检；更换机器若未复制调度文件，则先从原受控统计文件准备：

```powershell
python -m HFLSnF_KG_v5.run_multi_topology_dataset prepare
python -m HFLSnF_KG_v5.run_multi_topology_dataset validate
python -m HFLSnF_KG_v5.run_multi_topology_dataset formal3
```

`prepare` 为全部8个利用率、三方法、每个1,000轮构建映射并校验。`validate` 复算真实分区、初始化及150轮调度摘要，同批次相同分区只计算一次，写入 `artifacts/multi_topology_dataset/validation.json`。

默认训练按 HFLSnF、HFLnoSnF、FLnoSnF 顺序独立启动子进程，结果位于 `results/multi_topology_dataset/open_wn18rr_seed42/`。检测到损失或验证指标非有限时终止当前子进程，并停止后续实验。

失败或中断后使用已有清单恢复：

```powershell
python -m HFLSnF_KG_v5.run_multi_topology_dataset formal3 --resume "<batch_summary.json的路径>"
python -m HFLSnF_KG_v5.run_multi_topology_dataset report --batch "<batch_summary.json的路径>"
```

恢复时校验配置、数据、调度、分区、共同初始化及已完成检查点摘要。已通过且未改变的实验跳过；失败实验从头重跑，不支持轮内续训。报告只展示验证指标。

其他组合可以复制三份配置、更改选择字段，并显式传入配置列表：

```powershell
python -m HFLSnF_KG_v5.run_multi_topology_dataset validate --configs "<第一份.yaml>" "<第二份.yaml>" "<第三份.yaml>"
python -m HFLSnF_KG_v5.run_multi_topology_dataset formal3 --configs "<第一份.yaml>" "<第二份.yaml>" "<第三份.yaml>"
```

正式训练完成后，对每个实验目录分别完整测试：

```powershell
python -m HFLSnF_KG_v5.run_best_checkpoint_official_evaluation --dataset wn18rr --result-dir "<实验目录>" --using-gpu --require-cuda
```

该入口恢复最佳检查点，核对实体关系映射，使用全体实体候选精确过滤排名；WN18RR 完整测试应为3,134条、6,268次头尾查询。输出头、尾、综合的 MRR、Hits@1/3/10、平均排名及查询数。

## 产物与本机验证边界

训练目录保留配置快照、数据摘要、实体与关系映射、客户端分区摘要、逐轮参与及聚合审计、逐轮指标、最佳模型和汇总。批次另存每次启动配置、进程日志、输入摘要与状态清单；正式结果验收会核对完整轮数及最佳轮次是否来自验证MRR。

本机使用 Python 3.7、PyTorch 1.13.1+cpu。新测试覆盖关系域分区、文本与错误路径、真实受控人数、切换拓扑规模、三方法临时小图训练及完整测试、失败恢复、检查点改变拒绝及无CUDA拒绝。原真实 FB15k-237 编号和分区摘要也已核对。

完整回归发现既有 `run_fedadam_stage2.py` 引用的 `reports/gen_fedadam_stage2_report.py` 在当前目录缺失，导致该历史测试模块无法导入；该报告模块不在本轮实现范围内。其余测试的结果及最终复验记录保存在 `artifacts/multi_topology_dataset/` 和项目工作日志中。

迁移时需同时携带真实数据和重建调度，或携带原受控统计文件后执行 `prepare`；这些数据与 MAT 文件受仓库忽略规则影响，不能假设仅同步代码就已包含。
