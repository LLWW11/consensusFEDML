## 一、代码现状诊断：一个被浪费的非互斥结构

读完三个项目，最关键的发现是：**`build_hypergraph_structure.m` 其实已经构造了一个非互斥加权关联矩阵，但下游把它坍缩回了互斥分配。**

### 1.1 证据链

| 文件 | 行为 | 问题 |
|------|------|------|
| `build_hypergraph_structure.m` L29-119 | `H_ce(i,j)` 逐层累加路径带宽 ÷ 跳数，归一化后中位数裁剪 → 客户端对多个 edge 有连续权重（非互斥） | 结构本身是对的 |
| `hypergraph_GNN_core.m` L174-203 `generate_assignment_from_embeddings` | 对每个 client 取 `best_edge = argmax score` | **最后一步把非互斥矩阵坍缩成"每客户端 1 个 edge"**，加权信息全丢 |
| `hyper_snf.m` L508-523 ILP 约束1 | `Σ_{h: c∈h} x_h ≤ 1`（客户端唯一性） | 硬性互斥，强制单路径 |
| `hyper_snf.m` L329 Phase 4 注释 | "贪心构造超边（逐个滑动窗口，**无重叠分段**）" | 超边本身就不重叠 |
| `Topo_opt` → `result-U-v2.3-*.mat` | 固定 edge 集 + 固定 `c2e_map`，喂给 `trainer_test.py` | 整个 FL 探针跑在静态、互斥、单路径分配上 |

### 1.2 关键判断

"超图改聚合权重无效"这个实验结论其实不意外——因为超图结构在进入聚合前就已经被互斥化坍缩了，HGNN 学不出本该存在的高阶关系。

**突破口不是"换个超图用在哪"，而是"别再坍缩它"。** 让非互斥的关联矩阵直接驱动编排/路由层。

### 1.3 当前数据流（待打破）

```
gen_random_tsmlg_v3.m  →  TSML_BdwMat (N×N×T)
        │
        ▼
Topo_opt / LocalSearch_EdgeSet_v7  →  result-U-v2.3-*.mat (固定 edge 集 + c2e_map)
        │
        ▼
build_hypergraph_structure.m  →  加权非互斥 H_ce  ← 这里本应保留
        │
        ▼  (坍缩点)
hypergraph_GNN_core.m argmax  →  每客户端 1 个 edge  ← 非互斥信息丢失
        │
        ▼

        │
        ▼

```

## 二、三种非互斥超图构建方法（贴合现有代码）

### 方法 A：加权关联矩阵（已有，只需保留不坍缩）

`build_hypergraph_structure.m` 的做法保留，但把关联强度的语义从"特征"升级为"路由候选权重"：

```
H(i,j) = w₁ · (bw_ij / bw_max)          // 带宽维度：来自 TSML_BdwMat 路径瓶颈
       + w₂ · exp(-d(c_i, e_j) / T)       // 时效维度：来自 hyper_snf.m 的 d_mat 最早到达层
       + w₃ · P(link active over win)     // 可靠性维度：来自 gen_random_tsmlg_v3 的 percent 参数
```

这三项在 `hyper_snf.m` 里都已算过——`bw_mat`、`d_mat`、`percent` 均已存在。唯一改动：**不要在最后 argmax 选一个 edge**，而是把 `H` 整体保留作为路由表。

**特点**：实现成本最低，直接复用现有计算；非互斥性来自"一个 client 对多个 edge 有非零权重"。

### 方法 B：时空超图（从 TSMLG 直接构建，最贴合 SnF 语义）

这是 TSMLG → 时空超图路线，也是最有价值的方向。当前 `hyper_snf.m` 的 Phase 1-2 已经在时空扩展图（`tsmlg2adj` + 存储边）上算了 `d_mat`，但超边本身还是"静态聚合组"。真正的时空超图应该是：

- **顶点**：`(物理节点, 时间层)` 对，即 `tsmlg2adj.m` 展开后的 `N×L` 个节点
- **超边**：一次完整的聚合事件 $e_{st} = \{(c_1,t_1), (c_2,t_2), \ldots, (e, t_{agg})\}$，其中 $t_i \leq t_{agg}$，且每个 $(c_i, t_i) \to \ldots \to (e, t_{agg})$ 在时空图上可达
- **关联值**：$H_{st}((c_i,t_i), e_{st}) = \text{该段路径的瓶颈带宽}$（连续值，非 0/1）

这直接把 `hyper_snf.m` Phase 5 的"时空扩展图 maxflow"显式化成超边。一个客户端 $(c, t_1)$ 可以出现在**不同 $t_{agg}$ 的多条时空超边里**——天然非互斥，因为它代表"在不同时间窗被聚合"的多种可能。

**特点**：非互斥性来自时间维度；显式建模存储转发；超边带时间属性，天然支持时隙调度。

### 方法 C：可靠性/概率超图（适合抗断链场景）

`gen_random_tsmlg_v3.m` 里 `percent=0.3` 控制链路活跃概率。可以构造：

```
H(i,j) = P( client i 在 win 内能到达 edge j )
       = 1 - ∏_{t=1}^{T} (1 - p_reach(i, j, t))
```

这是概率软关联，客户端对所有 edge 都有非零概率（除非完全不可达）。适合做带冗余的路由。

**特点**：非互斥性来自概率软化；适合高断链率（低 percent）场景；可与方法 A/B 叠加（作为 H 的可靠性维度）。

### 三种方法对比

| 方法 | 非互斥来源 | 改动量 | 时序建模 | 适合场景 |
|------|-----------|--------|---------|---------|
| A 加权关联 | 多 edge 非零权重 | 最小 | 无 | 快速验证、路由表 |
| B 时空超图 | 时间维度多窗 | 中 | 有 | SnF 调度、时隙编排 |
| C 概率超图 | 概率软化 | 小 | 弱 | 高断链、冗余路由 |

## 三、非互斥超图能做什么（避开聚合权重，聚焦编排/路由）

已知"超图改聚合权重无效"——在互斥结构上学聚合权重等于在单路径上调系数，自由度太低。但非互斥超图在**通信编排层**的自由度是完全不同的。下面按编排调度、上传、下发路由展开。

### 3.1 上传多路径路由（超图 k-路流分解）

互斥超图下每个 client 只有一条 $(c \to e \to cloud)$ 路径。非互斥 $H$ 给了 client 到 k 个 edge 的候选，路由问题变成：

> 在加权超图上，为每个 client 的梯度/模型更新选一组（可重叠的）超边路径，使总完成时间最小、且不违反 edge 容量。

这本质是**超图上的多商品流**，比 `hyper_snf.m` 现在的"虚拟源汇 maxflow"丰富——maxflow 只给吞吐量上界，不给"谁走哪条"的调度。具体做法：

- 把 client 的上传量按 $H(i,:)$ 权重拆分到多条超边（类似 ECMP）
- 用超图边着色给重叠超边分配时隙（冲突的不能同时发）
- **收益**：降尾部延迟（一个慢 edge 不再阻塞整个 client）、抗断链（一条路径挂了走另一条）

### 3.2 下发广播编排（反向超图覆盖）

目前只优化上传（C2E + E2C）。但 HFL 每轮还有**云 → 边缘 → 客户端的全局模型下发**，这块在当前代码里完全没建模。非互斥超图特别适合：

- 构造**下发超图** $H_{down}$：超边 $= \{cloud, e, c_1 \ldots c_n\}$，表示一个广播组
- 非互斥 = 一个 client 可从多个 edge 接收（冗余下发，抗丢包）
- 问题变成**超图覆盖 / 集合覆盖**：选最少超边覆盖所有 client，或带时延约束的最小完成时间覆盖
- 在 `percent=0.3`（链路 70% 时间不活跃）的场景下收益明显——单路径下发会有大量 client 收不到

### 3.3 SnF 时隙调度（时空超图边着色）—— 最直接扩展现有代码

`hyper_snf.m` Phase 5 已经在时空扩展图上算了 E2C maxflow + 最早到达层。但没有回答"**哪个 edge 在哪层缓冲、哪层转发**"。时空超图把这变成了显式调度：

- 每条时空超边 $e_{st} = \{(c_1,t_1), \ldots, (e, t_{agg})\}$ 带一个时间属性 $t_{agg}$
- 调度 = 给超边分配时隙，使**共享物理链路的超边不同时占用**（边着色）
- 非互斥让一个 edge 可以在 $t_2$ 缓冲一批、$t_3$ 再缓冲一批（多超边），而不是 `hyper_snf.m` 现在的"一个 edge 一条 E2C 超边"
- 这是把 SnF 从"可行性判断"升级成"最优调度"

数学上就是超图边着色（chromatic index），可用贪心或 ILP，比现在 Phase 6 的 ILP 多一类变量（时隙分配）。

### 3.4 HGNN 做路由策略学习（不是做聚合权重）

这点要和"超图改聚合权重无效"区分开。聚合权重是**数值参数**，HGNN 学它确实自由度低。但 HGNN 做**路由决策**是离散结构输出，完全不同：

- **输入**：时空超图，节点特征 $=$ (当前队列长度、带宽状态、模型 staleness、剩余电量)
- **超图卷积** $D_v^{-1/2} H W_e D_e^{-1} H^T D_v^{-1/2} X \Theta$ 捕获"哪些 client-edge 组同时争用链路"这类高阶依赖——这正是普通 GNN（成对边）抓不到的
- **输出**：每个 client 的路由分布（softmax over 候选超边）
- **训练**：RL，reward $=$ 轮完成时间 $+$ 能耗 $-$ staleness 惩罚
- `hypergraph_GNN_core.m` 的 message passing 骨架（L62-106）可以直接复用，只改 `generate_assignment_from_embeddings`——从 argmax 选单 edge 改成输出路由分布

### 3.5 超图划分（客户端-edge 软分配）

经典应用：划分超图使跨分区通信最小、同时均衡各分区负载。

- 每个分区 $=$ 一个 edge 的 client 集
- 非互斥 → 软划分 → 允许在收益处重叠
- 工具：hMETIS、KaHyPar、Zoltan
- 目标：最小化跨分区通信（可去多个 edge 的 client）
- 可与方法 A 的加权 $H$ 结合，作为 ILP 的初始化

## 四、对联邦 KGE 的特殊机会

结合 `HFLSnF_KG_v3` 方向，这是发散但契合的点。KGE 里每个 client 持有部分三元组，更新的是**特定实体/关系**的嵌入。可以把"知识结构"和"拓扑结构"耦合进同一张超图：

- **知识超边**：$\{client_i, entity_e, relation_r\}$ 表示 client_i 持有含 $(e, r, *)$ 的三元组
- **拓扑超边**：$\{client_i, edge_j\}$ 来自方法 A/B
- **联合超图**的关联矩阵 $H_{joint}$ 同时编码"谁有这个实体的知识"和"谁能到达这个 edge"
- **用途**：编排**按实体分组的异步上传**——只更新同一实体的 client 才需要进同一聚合组，不同实体可并行走不同 edge。这比按 client 笼统分组高效得多，尤其 server bias correction 场景下能精确控制哪些实体更新汇聚

## 五、推荐起步路径

按改动量从小到大：

| 步骤 | 改动 | 内容 | 验证目标 |
|------|------|------|---------|
| 1 | 最小 | 停掉 `hypergraph_GNN_core.m` 的 argmax 坍缩，直接把加权 $H$ 输出给 Python 侧当**路由表**（替代现在从 `.mat` 读固定 c2e_map） | 看非互斥候选集长什么样 |
| 2 | 小 | 在 `hyper_snf.m` Phase 5 后加一个**超图边着色 ILP**，给时空超边分配时隙 | 把现有 maxflow 结果"激活"成可执行调度 |
| 3 | 中 | 补一个 $H_{down}$ 构造 + 覆盖 ILP，补齐上下行对称性 | FLSnF/HFLSnF 对比多一个下行维度 |
| 4 | 大 | 等 1-3 跑通有 baseline 后，用 RL + HGNN 学路由 | 有真实 reward 信号后端到端优化 |

**建议第一步先做步骤 1 + 2**：前者打开非互斥信息通路，后者把 SnF 升级为可调度，两者都不动聚合层，风险可控且有明确的对比基线。
