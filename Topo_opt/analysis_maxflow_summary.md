# Old_version 最大流实现分析

## 整体架构：HFL-SnF（分层联邦学习选择与转发算法）

Old_version 中的最大流实现用于解决**分层联邦学习中的边缘节点选择与客户端流量调度**问题。核心思路是：将网络拓扑构建为图模型，利用**最大流算法**分两阶段完成"客户端→边缘节点→云服务器"的端到端映射。

---

## 一、核心算法流程

### Phase 1: 客户端 → 边缘节点（Client-to-Edge）

**目标**：在满足带宽约束的前提下，将尽可能多的客户端分配到边缘节点。

1. **构建辅助拓扑**（`tsmlg2adj.m`）
   - 将 TSMLG（时隙多层图）的带宽矩阵 `TSML_BdwMat` 转换为有向图邻接矩阵 `AuxTopo`
   - 同一节点在不同层之间用 `Cost_of_TemporalLinks（inf）` 权重连接，表示时隙链路代价极高，算法会尽量避免使用

2. **添加虚拟节点**（`add_vnode_vedge_v2.m`）
   - 添加**虚拟源节点**（ID = N*L+1）和**虚拟汇节点**（ID = N*L+2）
   - 虚拟源 → 所有客户端节点，边权重 = 1（表示每个客户端提供 1 个单位的流量）
   - 所有层上的边缘节点 → 虚拟汇，边权重 = inf（表示汇聚能力无限，只受带宽限制）

3. **计算最大流**（`maxflow` 函数）
   - 在构建好的有向图 `G_vC2E` 上调用 MATLAB 内置 `maxflow` 算法
   - 最大流值 = 成功汇聚到边缘节点的客户端数量

4. **提取映射关系**（`C2E_Mapping_v4.m`）
   - 遍历每个已连接的客户端，使用 `shortestpath` 找到其到虚拟汇的路径
   - 沿路径反向查找第一个遇到的边缘节点，记录映射 `c2emap{layer, edge_id}`
   - **逐客户端扣除已用带宽**：沿路径的每条边减去 1 的容量，边容量为 0 时删除该边
   - 这一步确保映射结果符合实际带宽约束

### Phase 2: 边缘节点 → 云服务器（Edge-to-Cloud）

**目标**：将第一阶段汇聚了客户端的边缘节点连接到云服务器。

1. **更新剩余带宽拓扑**
   - 从 `AuxTopo` 中减去第一阶段已消耗的带宽：`A_PostEdge = AuxTopo - A_usedBW`
   - 构建 `G_PostEdge` 有向图

2. **按优先级逐层尝试**（关键创新点）
   - 找出第一阶段中有效使用了哪些边缘节点、每个节点在哪层汇聚了多少客户端
   - 构建优先级列表：同一边缘节点**从最底层开始尝试**（priority_AggEdge_list 降序排列）
   - 逐轮尝试：每轮中每个边缘节点取当前可用的最高层

3. **添加虚拟节点并计算最大流**（`add_vnode_vedge_cloud.m`）
   - 对每一组候选边缘节点（Current_edge），添加：
     - 虚拟源 → 当前候选边缘节点，权重 = w_srcEdge
     - 云服务器各层节点 → 虚拟汇，权重 = w_dstEdge
   - 调用 `maxflow` 计算边缘到云的最大流

4. **终止条件**
   - 成功汇聚的边缘节点数量 = 实际使用的边缘节点数量 → 停止
   - 当前层尝试失败 → 降低层数继续尝试
   - 所有层尝试完毕仍失败 → 返回 0

### 最终输出

- `group_num_HFLSnF`：成功连接到云的边缘节点数量（即联邦学习的分组数）
- `client_num_HFLSnF`：每个边缘节点实际服务的客户端数量
- `max_layer`：汇聚的最大层数（用于计算传输时间）
- `actual_c2e_map`：客户端到边缘节点的完整映射表

## 二、外层优化框架（LocalSearch_EdgeSet_v7.m）

最大流算法内嵌在一个**局部搜索优化框架**中，用于选择最优的边缘节点集合：

### 1. 生成候选集（`Gen_Candidate_EdgeSet.m`）
- 根据跳数约束（MinHop, MaxHop, TargetHop）筛选候选边缘节点
- `TargetHop` 跳的节点作为初始解

### 2. 三种局部操作

| 操作 | 描述 | 条件 |
|------|------|------|
| **Open** | 向当前集合添加一个候选节点 | `optim_obj_temp < optim_obj_current && client_num >= current` |
| **Swap** | 用候选节点替换当前集合中的一个节点 | 同上 |
| **Close** | 从当前集合删除一个节点 | 同上 |

### 3. 优化目标（`OptimObj.m`）
```
value = 0.3 * (客户端数 / 37) - 0.3 * (总时间 / 200)
```
- `time1 = layers * 16 + 100`：传输时间（随层数增加）
- `time2 = (group_num + max(client_num)) * 2`：聚合时间
- 目标值越小越好

### 4. 停止条件
- 当优化目标不再改善，且客户端数不再增加时，再跑一轮后停止

## 三、关键设计特点

### 1. 虚拟节点技巧
通过添加**虚拟源和虚拟汇**，将"客户端→边缘→云"的映射问题转化为标准最大流问题，这是算法设计的核心技巧。

### 2. 分层网络建模
使用时隙多层图（TSMLG）建模不同时刻的网络拓扑，层间连接（temporal links）权重设为 inf，迫使算法优先使用同层内的连接。

### 3. 优先级调度
边缘到云阶段采用**从底层到高层逐层尝试**的优先级策略，因为底层传输延迟更低，有助于优化目标。

### 4. 带宽精确核算
在 C2E_Mapping 中逐客户端扣除路径带宽，确保映射结果满足实际带宽约束，最大流结果与真实映射一致。

### 5. 双层优化嵌套
外层用局部搜索选择边缘节点集合，内层用最大流评估该集合的客户端汇聚能力，形成完整的最优边缘节点选择方案。
