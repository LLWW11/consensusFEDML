# V2同MAT四臂TransE结果分析

## 一、技术结论

D臂已经完整运行并通过四臂公平性审计，但结果明确低于C。当前种子42下，最合理的结论不是“FedE目标单独有效”，而是：

> **FedE公平预算目标只有和行级所有权聚合组合时才表现出明显收益；放在稠密FedAvg中反而比原margin基线更差。**

C：`masked+FedE-fair`的完整官方测试集MRR为`0.197400`，D：`dense+FedE-fair`为`0.133568`，C比D高`0.063832`，相对高约`47.79%`。四臂MRR交互项为`+0.048765`，明显高于此前用于描述性筛选的`0.003`门槛。

这支持一个很强的机制信号：行级聚合不是FedE目标之外的一点小修补，而是在当前37客户端头实体划分下，让FedE式大幅局部更新能够保留下来的关键条件。

不过当前仍只有一个训练种子，因此“正交互”是描述性结论，还不能写成统计显著或跨种子稳定结论。

## 二、结果完整且四臂可直接比较

四臂汇总状态为`comparable`，D臂管理任务状态为`completed_and_compared`。A、B、C、D共同满足：

- 客户端划分哈希相同；
- 200行MAT调度哈希相同；
- 初始模型参数哈希相同；
- 37个候选客户端；
- 每轮参与11至37个客户端，平均35.73个；
- 200个通信轮、每轮1个本地epoch；
- 256维嵌入、5个负样本、批次4096、学习率0.001；
- 相同的完整官方测试集；
- 全局候选、全局filtered、头尾双向评估；
- 测试集20,466条事实，共40,932个排名查询。

D在`cuda:0`完成200轮，没有训练中断、非有限损失或检查点缺失。日志开头的`torchvision`图像扩展警告与TransE训练无关，不影响本次结果。

## 四、二乘二回答了什么

| 对比 | MRR变化 | 相对变化 | Hits@3变化 | 解释 |
|---|---:|---:|---:|---|
| B-A | +0.015067 | +9.79% | +0.017615 | margin下，行级聚合有效 |
| D-A | -0.020366 | -13.23% | -0.012728 | 稠密聚合下，FedE目标反而退化 |
| C-B | +0.028399 | +16.80% | +0.029024 | 行级聚合下，FedE目标有效 |
| C-D | +0.063832 | +47.79% | +0.059367 | FedE目标下，行级聚合非常关键 |

交互项为：

```text
(C-B) - (D-A) = +0.048765 MRR
```

如果两项改动只是简单相加，交互项应该接近0。现在FedE目标在稠密聚合下是负收益，在行级聚合下却是正收益，所以当前证据更符合“二者存在强正交互”。

不能把这个结论扩大成“FedE目标在所有联邦知识图谱任务中都依赖行级聚合”。它只适用于当前FB15k-237、37客户端头实体划分、统一全局嵌入表、当前MAT参与调度和当前本地预算。

## 五、训练曲线解释了D为什么差

C与D使用同一个FedE本地目标，并且第1轮加权本地损失完全相同，都是`20.156588`。从第2轮开始，两者只因聚合语义不同而走向不同的全局模型。

| 通信轮 | C：masked+FedE损失 | D：dense+FedE损失 |
|---:|---:|---:|
| 1 | 20.1566 | 20.1566 |
| 50 | 8.5938 | 10.1007 |
| 100 | 2.2155 | 4.7357 |
| 150 | 0.3584 | 2.7388 |
| 200 | 0.1908 | 2.1244 |

到第200轮，D的本地损失仍约为C的`11.1`倍。因为每轮客户端都从上一轮全局模型出发，这说明D聚合后的全局参数持续丢失或稀释了有效局部更新，下一轮客户端不得不重复解决相似错误。

D的1000条固定验证事实MRR在第50轮达到`0.125965`，第120轮达到最高`0.131287`，之后一直在约`0.128`至`0.131`之间波动。与此同时：

- Hits@10从第50轮的`0.2090`继续升至第200轮的`0.2670`；
- Hits@1却从`0.0850`下降到`0.0590`；
- MRR没有随训练损失继续下降而明显提高。

大白话解释是：D仍在把一部分正确实体推入前10名，但无法稳定地推到第1名或前3名。继续给D增加相同训练轮数，大概率只会缓慢改善Hits@10，不能自动解决稠密平均造成的更新稀释。

C则不同。它的监控MRR从第100轮`0.165895`持续提高到第200轮`0.206150`，Hits@1、Hits@3和Hits@10也整体提高。C在第200轮仍未表现出明显收敛，但这不等于现在应该只延长C；单独延长C会破坏当前公平预算。

## 六、为什么高覆盖率下行级聚合仍然有效

C平均每轮更新约14,437个实体行，只回退约104行；237个关系行中平均更新236.97行。也就是说，大部分行在每轮都至少有一个活跃拥有者。

因此，C优于D的原因不只是“某些行在D中完全没有更新”。更关键的是：

- D按客户端三元组数平均完整嵌入表；
- 对某个具体实体或关系没有本地正知识的客户端，其未变化参数也进入平均；
- 真正拥有该知识行的客户端更新被大量未变化副本稀释；
- C只让本轮拥有该正三元组知识的客户端参与对应行的平均；
- 负采样偶然访问的实体行不获得聚合所有权。

FedE自对抗目标产生的局部更新比margin目标更强。在D中，这些更新被完整表平均稀释；在C中，它们由知识拥有者之间直接合并，因此C与D的差距比B与A更大。

这是当前最有证据支持的机制解释，但仍属于基于代码语义和训练曲线的诊断，不是单独测量每行梯度稀释率后的因果证明。

## 七、最新方向诊断不能用于正式结论

`directional_diagnostics_20260727_204432_218658`虽然状态为`completed`，但它实际使用：

- `using_gpu: false`；
- `max_triples: 8`；
- 只有16个头尾查询；
- 只包含A、B、C；
- 没有加载D检查点。

这仍是IDE默认CPU冒烟，不是计划中的完整方向诊断。8条事实产生的头尾MRR和逐关系结果方差极大，不能用于解释C-D差异，也不能写入论文。

这属于高影响的评估配置问题，而不是模型结果问题。四臂完整测试指标可信；最新方向诊断只证明代码链路可运行。

## 八、下一步建议

### 1. 先补完整方向诊断，不需要重训

在CUDA环境中使用完整官方测试集，并显式加入D：

```bash
python -m HFLSnF_KG_v2.run_directional_diagnostics \
  --result-root HFLSnF_KG_v2/results/三种 \
  --result dense_fede_fair=HFLSnF_KG_v2/results/hflsnf_kg_v2_four_arm_dense_fede_fair_cuda_20260727_194901_499171 \
  --using-gpu \
  --require-cuda \
  --max-triples 0
```

如果在当前本机复制后的双层`results/results`目录运行，需要把D路径改为实际的本地嵌套路径。

完整诊断重点回答：

- C-D提升主要来自头预测还是尾预测；
- D的Hits@10改善和Hits@1下降分别集中在哪些关系；
- C相对D是大量查询小幅胜出，还是少数查询大幅拉升。

### 2. 再做种子43和44

如果论文要同时论证“行级聚合”和“FedE本地目标”，应让A、B、C、D在种子43和44下全部运行。只有完整四臂多种子结果才能为主效应和交互项给出均值、标准差或置信区间。

如果服务器预算非常有限，可先复验C和D，因为`C-D`是当前最大的直接效应；但这只能验证最佳方案相对稠密FedE对照的稳定性，不能完整验证二乘二交互。

### 3. 多种子稳定后再拆FedE目标组合

C-B同时改变L1距离、尾负采样和自对抗逻辑损失。确认C稳定后，再在行级聚合条件下逐步拆分这三项，避免把全部提升归因于“自对抗损失”。

### 4. 暂时不要做的事

- 不要仅延长C到300或400轮后与当前200轮A、B、D直接比较；
- 不要先运行256负样本、3本地epoch的高开销FedE论文配置；
- 不要根据8条方向冒烟结果选择关系或负采样策略；
- 不要把C略高于集中式参考的`0.001829`写成稳定超过集中式。

## 九、当前可用于论文的表述

当前可以写成：

> 在固定客户端划分、动态MAT调度、初始模型和训练预算下，行级所有权聚合将margin目标的测试MRR从0.1539提高到0.1690；FedE公平预算目标在行级聚合下进一步提高到0.1974，但在稠密FedAvg下下降到0.1336。单种子二乘二结果显示正交互，说明FedE式本地目标的收益依赖于能够避免无关客户端稀释知识行更新的聚合语义。

当前不能写成：

- “正交互已经统计显著”；
- “自对抗损失单独贡献了全部提升”；
- “HFLSnF拓扑本身提高了精度”；
- “C已经稳定超过集中式或FedE原论文结果”。
