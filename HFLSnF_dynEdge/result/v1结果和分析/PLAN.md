# 200 客户端两级采样训练改造

## 目标流程

每个本地 epoch 严格执行：

1. 全部 200 个客户端各完成一次本地训练。
2. 从 200 人中均匀、无放回随机抽取 37 人，作为候选客户端。
3. 读取 MAT 当前 epoch 的各边缘组人数。
4. 将 37 人随机打乱，按各组人数依次截取，得到最终参与客户端。
5. 37 个候选客户端执行聚合前探针；最终参与客户端执行边缘/云端聚合。
6. 根据 YAML 配置向最终参与者或全部 200 人下发云模型。
7. 使用最终云模型在完整 MNIST 训练集和测试集上计算本轮指标。

## 关键修改

- 在 [topology_schedule.py](D:\1\1myworkcode\HFLSnF_dynEdge\topology_schedule.py) 中拆分“真实客户端池”和“MAT 拓扑槽位”：
  - MAT 的 37 个节点只表示拓扑容量，不再要求等于 `client_num_in_total`。
  - 对外提供每个 epoch 的有效组、边缘节点、各组人数和总参与人数。
  - 校验 `client_num_per_round=37` 与 MAT 拓扑容量一致，并校验各组人数之和不超过 37。
  - MAT 行改由展平后的 `global_epoch` 索引；总 epoch 数超过 MAT 的 200 行时启动即报错。

- 在 [trainer_test.py](D:\1\1myworkcode\HFLSnF_dynEdge\trainer_test.py) 中重排训练链路：
  - 保留全部 200 客户端训练，并将采样移动到本地训练完成之后。
  - 删除“随机偏移后连续取 37 人”的方式，改为均匀无放回采样。
  - 两级采样分别使用局部随机数生成器，种子由 `random_seed`、`global_epoch` 和采样阶段确定，不污染全局 NumPy 随机状态。
  - 二次采样只采用 MAT 的各组人数；随机排列候选 37 人后按组配额切分，确保组间无重复、总人数精确匹配 MAT。
  - 客户端探针固定输出 37 个候选客户端；边缘探针输出最终各组模型；云探针输出最终云模型。
  - 聚合只读取最终参与客户端已经完成训练的本地状态，不重复训练。
  - 准确率测试显式接收 `w_global`，只评估最终云模型，不评估客户端私有模型；在 200 个客户端分区合并后的完整数据上计算加权准确率和损失。
  - MAT 参与人数为 0 时保留上一云模型，边缘探针留空，仍记录候选探针、云探针和云模型准确率，但不聚合、不下发参数。

- 配置和输出接口：
  - 根配置及 `configs/` 下实验配置统一使用 `client_num_in_total: 200`、`client_num_per_round: 37`。
  - 新增 `model_distribution_scope: "active" | "all"`，默认 `active`：
    - `active`：仅向最终二次采样客户端下发。
    - `all`：存在有效聚合结果时向全部 200 个客户端下发。
  - 每个 epoch 都测试云模型，相关实验配置统一设置 `frequency_of_the_test: 1`。
  - `topology_schedule.jsonl` 改为逐 epoch 记录候选 37 人、MAT 各组配额、最终分组、最终参与者及实际下发范围，使探针列和真实客户端 ID 可追溯。
  - 使用简体中文更新 README；所有新增或修改的函数、方法均补充简体中文说明和必要代码注释。

## 测试计划

- 更新现有拓扑测试，确认 MAT 的 37 个槽位可以与 200 个真实客户端池共存，并继续覆盖四种拓扑场景、未知利用率和动态边缘容量。
- 新增 [test_hierarchical_sampling.py](D:\1\1myworkcode\HFLSnF_dynEdge\test_hierarchical_sampling.py)：
  - 首次采样为 200 中的 37 个唯一客户端，同种子同 epoch 可复现，不同 epoch 结果变化。
  - 二次采样结果属于候选 37 人，组间无重复，各组人数和总人数严格等于 MAT。
  - 覆盖总人数 37、部分参与和 0 人参与的代表 epoch。
  - 验证每个 epoch 全部 200 人都训练，只有最终参与者进入聚合。
  - 分别验证 `active` 和 `all` 两种参数下发范围。
  - 验证客户端探针始终对应候选 37 人，准确率始终来自最终云模型。
  - 验证运行时采样记录与实际聚合、下发集合一致。
- 执行全部单元测试，再运行 HFL 三轮和 FL 一轮冒烟实验，检查探针行数、指标行数、采样日志和模型下发行为。

## 默认约定

- “每个 epoch”指展平后的本地 epoch；当前 `comm_round=200`、`group_comm_round=1`、`epochs=1` 时，恰好对应 MAT 的 200 行。
- MAT 只提供各边缘组的参与数量，不使用其中的具体物理客户端 ID 选择真实数据客户端。
- 参数下发默认采用 `active`；只有显式配置为 `all` 才广播给全部 200 人。
